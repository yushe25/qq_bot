## T-21 QQ 传输安全边界

- `qq.wsUrl`、`qq.httpUrl` 默认只允许 `127.0.0.1`、`localhost`、`::1`。
- 非回环地址且 `qq.allowRemote=false` 时配置校验失败。
- 非回环地址且 `qq.allowRemote=true` 时允许构建并记录 WARN，不输出 Token。
- 当前实际配置为回环地址，`allow_remote=false`，QQF 启动正常。
- NapCat 真实复检结论为 `loopback_only`，详情见 `T-21-napcat-auth-20260915.md`。

## T-22 安全出站 @

- `qq_send_group_message` 支持 `mentionUserIds`，最多 5 人。
- 空值、重复、非数字、超限在 Tool 层拒绝。
- SafetyPipeline 使用当前群成员列表校验 mention；非成员或成员接口失败整条消息 fail-closed。
- 文本拆分时只有第一段携带 @。
- OneBot payload 顺序为 `reply`、`at`、`text`；mention 场景不携带 `auto_escape`。

真实协议 P08：

```text
target_found=True
result_ok=True
mention_count=1
```

项目方确认真实群显示蓝色 @。该测试使用真实 NapCat、真实成员列表和产品 SafetyPipeline；
模型侧连续两次返回空文本，没有产生 mention tool call，作为模型输出风险单独记录。

## T-08 控制台 Token 泄漏面

- HTTP 只接受 `Authorization: Bearer <token>`，URL 查询参数不再接受长期 Token。
- 新增 `POST /api/ws-ticket`，ticket 有效期 60 秒、单次使用、绑定来源。
- `WS /ws/live` 只接受 ticket；旧 `?token=` 连接被拒绝。
- 控制台页面公开为静态资源，启动后通过 Token 按钮录入；不把长期 Token 写入 URL。

覆盖测试：

- 长期 Token 查询参数返回 401。
- ticket 成功连接一次，重放失败。
- 过期 ticket 失败。
- 来源不匹配的 ticket 失败。
- 旧 WS `?token=` 失败。
