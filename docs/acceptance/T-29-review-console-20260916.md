## 一、交付范围

- 素材审核状态从 `inbound_media` 扩展到 `inbound_media_groups`，唯一键为
  `(media_id, group_id)`。
- 审核列表默认跨全部白名单群汇总，支持稳定游标分页；A 群批准或拒绝不影响 B 群。
- 支持名称、说明、标签、情绪、适合场景和避免场景六类元数据编辑。
- 支持审核列表滚动加载、审批后按原展开数量保位刷新。
- 图片预览改为带 Bearer Header 的 `fetch`、`blob:` Object URL 和显式释放。
- 唤醒日志与审计日志合并为统一时间线，支持全部、唤醒、审计三种筛选。
- 控制台页面顺序调整为：状态栏、统计卡片、会话列表与实时事件、素材审核、日志时间线。

页面实测行为：

- 审核卡片显示来源群、抓取时间、重复次数、mime、字节数、置信度和语义元数据。
- 批准前保存未提交修改；保存失败时不批准。
- 批准成功、元数据更新和拒绝操作均写入审计，并立即出现在日志时间线。
- 窄屏下计算样式为 `grid-template-columns: 1fr`，长标签和说明自动换行。
- 日志类型同时使用文字和颜色区分，筛选切换时列表和游标正确重置。

## 五、验收中发现并修复

1. 同一素材来自多个群时，原审核状态只保存在 media 级，无法按群隔离。现由
   `inbound_media_groups.review_status` 保存群级状态。
2. 同一素材批准到多个群时，manifest 的 `source_group_ids` 和 `scope_groups` 需要合并，
   不能只保留最后一次操作的群。当前工作区修复已在验收中覆盖。
3. 拒绝操作不应立即移动共享文件，只有所有群关联都拒绝后才移动到 `rejected/`。
   当前工作区修复已在验收中覆盖。
4. 浏览器不能直接通过裸 `<img src>` 访问受保护预览；前台已改为 Bearer fetch 和 Object URL。
5. Codex 内置浏览器不支持 `window.prompt()`，Token 模式使用本机代理模拟等价的
   `sessionStorage` 状态完成验收，不修改应用代码。
