# 0005. 表情改为语义选择并支持独立自动标注

- 状态：accepted
- 日期：2026-09-15
- 关联文档：docs/design-contracts/sticker-media.md、docs/design-contracts/schedule-behavior.md

## 背景

旧实现先让模型生成文字，再由运行时按 persona 概率随机追加一张表情。模型既不知道
素材库有哪些图片，也不知道每张图片的含义，因此无法判断表情是否贴合语境。自动追加还会
绕过模型的完整决策，出现“严肃场景随机贴图”和“没有合适素材也强行贴图”的问题。

## 决策

- 删除运行时随机追加表情的主路径，表情由模型根据可读素材目录主动调用 `sticker_send` 选择。
- 每轮最多发送一张表情；同轮文字加表情和纯表情都允许，不同轮次可以重复使用同一素材。
- 没有合适素材时必须发送纯文字，不退化为随机兜底。
- 素材清单扩展名称、说明、标签、情绪、适合场景、避免场景和标注来源等语义字段。
- 自动标注使用与聊天模型完全分离的 OpenAI-compatible 视觉 Provider 配置和密钥。
- 自动标注结果立即写入 manifest 并生效，允许项目方事后人工修改；运行中的 QQF 不热加载，
  修改后需要重启。
- `sticker_only_probability` 和 `sticker_with_text_probability` 保留解析兼容但标记为 deprecated，
  不再参与选图。

## 后果

优点是模型获得足够的素材语义，能主动选择纯文字、纯表情或图文组合，减少不贴合语境的贴图。
代价是每次唤醒需要注入受限长度的素材目录，且模型可能少发或不发表情；项目方先观察真实数据，
不使用随机补偿。自动标注存在隐私、费用和错误标签风险，因此密钥只能来自环境变量，图片先经
MediaGuard，生成结果必须清洗后原子写入，并保留人工覆盖能力。

回滚方式是关闭 `sticker.enabled` 或恢复旧版本运行时；旧概率字段在后续版本单独删除。
