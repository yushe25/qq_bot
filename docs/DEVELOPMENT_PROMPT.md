## 项目本质与范围边界

QQF 是自托管的 QQ 仿真群友运行时：机器人在小群里要像真人一样潜水、冒泡、接梗、发短句和表情包，长期保持人格、记忆、作息和说话风格一致。

范围边界：

- 私人项目，最多 20 人的小群；单机、单实例、Python 3.12+。
- 只接入 OneBot v11 兼容实现（NapCat / Lagrange 等）。
- 禁止加入：Docker/k8s、多账号、多实例集群、企业级控制台、RAG 知识库、语音合成、图像生成、Node.js 依赖、面向大群的能力。
- 禁止把 `config.json`、`config.txt`、`state/`、真实群号或任何密钥写入仓库或提交记录。
- 没有设计契约的新功能不允许进入实现；已有契约在实现后同步更新为 `implemented`。

## 第二阶段：按顺序完成以下清单

### 1. 工程化地基

- 如果目录还不是 git 仓库，先 `git init`，确认 `.gitignore` 能拦住配置、状态库、密钥和虚拟环境。
- 用 `uv lock` 或 `pip-compile` 生成依赖锁文件；不悄悄新增未声明的依赖。
- 补 `start.ps1`：设置 `PYTHONUTF8=1`，解决 Windows 中文日志乱码；提供 mock 与真实 OneBot 两种启动方式。
- 补齐 GitHub Actions：`pytest` + `ruff`；pyright 可用后加入。
- 日志统一显式 UTF-8 handler。

### 2. 稳健全链路

- 修复多工具批次中 `dive` 提前结束导致 tool history 不完整的问题：未执行的调用必须补“已取消”结果，或全部执行后再进入潜水。
- 会话历史截断不得把工具调用从中间切断，避免 OpenAI 兼容 API 400。
- LLM 调用增加重试与退避；失败时写审计，不允许死循环或卡死会话。
- 群成员数超过 `safety.maxGroupMembers`（默认 20）时只读不发言且写审计；成员列表查询失败时对发消息采取失败关闭。
- 迁移或完善现有 51 个测试，不在测试通过率上作弊。

### 3. 按契约实现三类核心功能

**表情与媒体**：按 `sticker-media.md` 实现本地白名单表情库、manifest、`sticker_send` 真实发送；入站图片/表情/语音/文件先摘要成 `[图片]`、`[表情:178:抠鼻]`、`[语音]`、`[文件]` 再给模型；MediaGuard 只允许白名单本地文件，禁止任意远程抓取。

**自主学习**：按 `learning-style.md` 实现观察、置信度、总结、持久化、过期和注入；只学表达方式与群聊风格，不学身份、隐私、账号信息；学习结果不能覆盖 persona 的自我认知和禁忌；写入前必须过 ContentFilter。

**作息与节奏**：按 `schedule-behavior.md` 实现活跃/安静时段、随机回复延迟、每日发送上限、重启后的状态恢复；表情由模型按语义目录主动选择，不再使用运行时随机追图；允许模型在安静时段潜水而不是硬性回复。

### 4. 记忆与私聊补齐

- `memory_update` 增加 kind 校验、过期、衰减和重要性排序；mock provider 与测试必须真实覆盖记忆写入与快照。
- 补 `qq_send_private_message` 及 owner 私聊完整链路；私聊同样经过白名单、限流、内容过滤、审计。
- 记忆快照限制条数和单条长度，避免把记忆变成 token 大坑。

### 5. Token 优化

- 少唤醒：降低普通消息唤醒概率、加长批处理窗口、提高发言后冷却。
- 压体积：唤醒只带最近 10~12 条消息，会话历史保留 24~30 轮，历史工具默认 8~10 条，工具结果与单条消息限长。
- 去重复：合并连续刷屏、压缩重复工具结果、去掉 persona 与系统提示中的重复规则。
- 工具层：没有实现的工具不进 schema，最终回复步骤不再携带全部工具定义。
- `max_tokens` 调到 200 左右；优先支持 prefix caching 的服务，保持 system prompt 与工具顺序稳定。
- 记录 prompt/completion token 到 wake_log，用真实数据调整预算。

### 6. 端到端验收

- 用 `scripts/mock_qq_server.py` 连续跑 30~60 分钟：消息、@、拍一拍、潜水、记忆、表情、限流、defer 全部可观测。
- mock 阶段必须出现记忆写入、表情发送、sleep/dive、多轮工具调用，并验证重启后状态一致。
- 更新 `README.md` 与 `docs/PROJECT_REPORT.md`：运行方式、配置说明、已支持功能、已知限制、NapCat/Lagrange 兼容性实测结果。

## 工作纪律

1. 一个阶段一个可验收结果，完成再进入下一阶段。
2. 先写或改测试，再实现；行为变化必须更新规格。
3. 模块边界保持：`platform/` 只做协议转换，`agent/` 负责模型与人格，`runtime/` 负责调度编排，`safety/` 负责所有对外动作门禁，`memory/` 与 `storage/` 负责持久化。
4. 不顺手重构无关代码，不删用户已有改动，不为了炫技重写现有实现。
5. 遇到文档没说清楚的方向，列出开放问题，不要自行扩大范围；已批准的 ADR 优先级高于聊天中的随口建议。
6. 安全路径不可绕过：白名单、内容过滤、限流、审计、成员数量护栏全部必须真实生效，而不是只写配置。
7. 所有出站消息必须经过 `SafetyPipeline`；模型输出必须拦截 CQ 码注入、密钥、手机号等敏感模式。
8. 最终交付时说明：哪些改动可逆、哪些配置必须由项目方填写、哪些风险尚未消除。
